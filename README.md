# Codex 额外额度购买：先分清 Credits、付费重置和升 Pro，再决定在国内怎么把这笔钱付出去

Codex 撞到限额的那一刻，屏幕上通常只给你一句 "You've hit your usage limit"，外加一个等待时间。急着交付的活还在手上，于是你打开搜索引擎，输入"Codex 额外额度购买"——然后发现官方帮助中心里的名词有一堆：Credits、Instant Reset、Banked Reset、Usage Dashboard。这些不是同一件事，买错了就是白花钱。

下面按"你缺的是哪种额度 → 官方怎么买 → 国内怎么付钱 → 哪种套餐组合更划算"的顺序讲清楚。

## 先搞清楚：你缺的不是一种"额度"

Codex 上其实同时跑着四套计量，触顶哪一套，处理方式完全不同。

第一套是**5 小时滚动窗口**。从你发出本窗口第一条消息开始计时，累计用一个会话池，用完就限流，等窗口过去才逐步恢复。它不是"睡一觉满血"的每日刷新。

第二套是**周额度**，7 天滚动，和 5 小时窗口独立计算。所以会出现"5 小时窗口还剩一些，但周额度已经满了"的组合状态。

第三套是**套餐续费周期**。这是最容易被误会的一套。

> 续费日不等于 Codex 额度重置日。每月 19 日扣款，只代表你的 Plus 或 Pro 资格续到了下个月，Codex 自己的使用周期是另一条时间线。

第四套才是**额外的额度余额**，也就是 Credits。它是加在套餐之上的按量余额，用完了套餐还得继续干活时才会被扣。

除此之外还有两个容易混进来的东西：付费的 Instant Reset 和官方赠送的 Banked Reset。它们操作的是"使用周期"，不是"余额"，后面单独说。

在 Codex CLI 里敲 `/status` 可以看当前剩余和重置时间；网页端进 Settings → Usage，能看到周额度剩余和下一次 reset 的具体时间。这两个数字，比账单页的"下次扣款日"有用得多。

## 官方买 Credits：入口、价格和几个容易踩的规则

套餐额度用完后，Codex 会在界面上给你一个"添加额度"的选项。正式入口是 Codex 的 Settings → Usage → Credits，网页端和 Codex 桌面应用里都能进。

价格上，Codex 仪表盘里上架的是 1,000 点数 40 美元的加油包。这个换算和 OpenAI 学生活动页面里的对应关系一致：面向美国和加拿大在校学生发放的 100 美元额度，到账显示为 2,500 点数。也就是说 1 点数大约等于 0.04 美元，买多少都是同一档单价。

几条写在官方说明里、但广告位不会提醒你的规则：

- 点数从购买日起 **12 个月内有效**，过期作废，不滚存、不结转；
- **不可退款**（法律强制要求的情形除外），不可转让、不可转售、不能赠送；
- 扣费顺序是**套餐额度优先**，只有套餐用尽后才开始动点数余额；
- 点数也不是 API 余额，两套账不通用；
- 在 Plus 和 Pro 档下，Codex、ChatGPT Work、Excel 共用同一份 agentic 使用额度，Word 也吃这份额度。你在 Codex 里买的点数，等套餐额度用完之后，这些功能都能花。

对 Plus 和 Pro 用户还有一个自动充值选项：在 Codex 的用量设置里设定"最低余额"和"目标余额"，余额掉到线以下时，系统用你账户里保存的默认付款方式自动补到目标值，只补差额。这个功能受你单独设置的每月支出上限约束——上限只作用于自动充值，一次性手动购买不受它管。另外注意负余额机制：如果一个任务开始时有余额、跑完之前被并发消耗清零，余额可能变成负数，之后买点数会先拿去抵这笔负数，再增加可用额度。

Free 和 Go 档的情况是不确定的：目前只有部分 Free 和 Go 用户能看到购买点数的入口。如果你的账户里没出现"添加额度"，那只是没开放给你，不是操作错了。

## 付费重置（Instant Reset）不是"再买一箱额度"

这是最贵的一次误解。

有媒体报道，部分 Plus 用户在使用额度耗尽后会看到一个"支付 8 美元重置额度"的黑色按钮。OpenAI 发言人对《商业内幕》的回应是，公司正在探索让额度用尽的用户额外购买使用时长的方案。同一批报道里提到，官方在更早的活动中还向符合条件的 Plus、Pro、Business 用户赠送过 Banked Reset，也就是可以存起来、以后手动用的"预存重置卡"，这类重置卡同样被用户当成了"额外送一份额度"。

实际逻辑不是加法。用掉一次完整重置后，5 小时额度和周额度都会被刷新，每周的重置日也会顺延到重置后重新计算的第七天左右。用数字说：你当前还剩 60%，花 8 美元重置，结果是从 60% 变成 100%，而不是 160%。那 60% 直接作废。

官方甚至建议过，如果你想把当前剩余额度先用掉，可以等额度消耗得差不多再买重置。判断自己该不该买，看一眼 Settings → Usage 里的 Codex 剩余百分比就够了，不用猜。

## 下单前必须想清楚的三件事

**账号归属。** 是往你自己已有的 ChatGPT 账号上续订，还是拿一个平台提供的成品号？这决定了你以后能不能自行管理密码、二次验证和账单，也决定了出问题时你的处理权有多少。能用自己的账号，就不要用别人的。

**续费是怎么执行的。** 这一条有公开记录可以参考。有博主完整记录过自己在 BeWild 购买的 3 个月 ChatGPT Plus：第二个月续订成功，第三个月 OpenAI 侧明确报出支付失败，原发票未付（一笔 982.14 菲律宾比索的账单），等了一个多小时客服后确认是自动续订所用的支付方式失败，平台退了部分款项 150.69 元，重新下单后经"继续任务"才完成，原发票作废、生成了新的 20 美元已付发票，订阅恢复正常。同期还有一位用户的情况是：一个 3 个月套餐未能按期自动续费，另购买的两个月套餐订单显示完成、但账号仍是免费版，客服恢复回复后，两笔订单分别获得退款处理或退款方案。

**退款路径有多长。** 黑猫投诉上另有一例记录：2026 年 4 月 16 日在同一个平台购买 ChatGPT Pro 充值，金额 210.99 美元（约合人民币 1400 元左右），时长为一个月，实际只用到 4 月 29 日就失效，投诉人称客服长期未回复。

这三件事放在一起看，结论不是"能不能用"——多数订单是正常交付的——而是"万一出问题，退款和处理要多久"。所以第一次用，选最短的周期试，拿到完整一个月的续订记录之后再考虑三个月或更长。

## 把现有额度用得更省，比买额度更划算

在掏钱之前，有几件事能明显拉长同一份额度的使用时间。

**给任务划边界。** "帮我检查整个项目"会让 Codex 把几百个文件塞进上下文，一个循环吃掉大量 token。改成"只检查 src/auth/ 下面的登录逻辑"，同样的结果，消耗差好几倍。重构任务同理，写明确切文件路径和"不要改动其他文件"。

**换轻量模型做轻活。** 同一套餐下，mini 档模型的额度条数是旗舰模型的好几倍。日常补全、写单测、修 lint 这类活完全不需要旗舰模型。可以用 profile 做切换：给省量模式单独写一个 config，日常走 mini、低推理强度，遇到复杂重构再切回默认。

**把 AGENTS.md 写短。** 这份项目说明每条消息都会被塞进去一次，啰嗦的项目说明相当于给每一轮对话加了一笔固定税。

**先要计划再动文件。** 让 Codex 先列修改计划，你确认之后再执行。模糊需求带来的反复试探，是额度流失最快的一种方式。

**盯周额度的节奏，而不是盯 5 小时窗口。** 有开发者实测估算过，一个完整的 5 小时额度大约相当于周额度的 15%，并把它简化成"5 小时看 10%、单日看 12%、5 小时上限 15%"三个数字。这是个人实测的估算，不是你账号的保证值，但作为判断自己消耗节奏的参照够用了。

## 几个被问得最多的短问题

**Credits 能退吗？** 不能，法律要求的情形除外。确认账号被盗用并联系支持后，官方会调查并可能恢复被消耗的点数。

**可以攒着慢慢用吗？** 可以，但只有 12 个月。过期不滚存。

**买点数会不会顺带提升套餐限额？** 不会。Free 或 Go 用户买点数也不改变套餐本身，套餐包含的限额原封不动。

**Credits 和 API 余额能互相顶替吗？** 不能。这是两套独立的账，API Key 走的是官方 API 费率单独结算。
